SECTION 01 · PROBLEM DEFINITION

왜 음성 인터페이스가 필요한가

사회적 배경

고령화·1인 가구 증가로 가정 내 작업 보조 수요 확대. 협동로봇은 케이지 없이 사람 옆에서 동작 가능한 차세대 폼팩터.

시장 동향

LLM·VLM 의 등장으로 자연어 → 의도 → 행동 변환의 기술 비용 급락. 비전문가도 쓰는 로봇이 가능한 시점.

왜 지금 이 프로젝트인가 — 시장 트렌드 + 본인 동기 1분 안에 전달.

SECTION 02 · BEHAVIOR TREE

한 명령이 여러 단계로 — BehaviorTree.CPP v3

<!-- bt_cobot2.xml --> <KeepRunningUntilFailure> <Sequence> <Action ID="PopNextTask" .../> <Fallback name="ActionPreparation"> <Sequence name="TargetRequiredBranch"> <Condition ID="IsTargetRequired"/> <Fallback name="SearchLogic"> <Condition ID="IsTargetLocated"/> <Action action_name="detect_in_place"/> <Action action_name="finding"/> </Fallback> <Action action_name="approach"/> </Sequence> </Fallback> <Action action_name="{action}"/> </Sequence> </KeepRunningUntilFailure> // PopNextTask 큐 빔 시 reset 1회 자동 emit → 홈 복귀
Groot 2 · KeepRunningUntilFailure → Sequence → PopNextTask → ActionPreparation Fallback
KeepRunningUntilFailure 가 sequence 큐를 돌리고, SearchLogic Fallback 이 탐색 자동화. 10 Hz tick.

# 캘리브 데이터 (20포즈 수집) T_gripper2camera = np.load( "T_gripper2camera.npy") # 4×4 mm # cv2.calibrateHandEye 으로 회전+병진 추정 R_g2c, t_g2c = cv2.calibrateHandEye( R_base2gripper, t_base2gripper, R_target2cam, t_target2cam, method=cv2.CALIB_HAND_EYE_TSAI) # 적용: camera_pose → base_pose base_pose = cam_pose_to_base_pose( pose, T_gripper2camera, base2gripper)

SECTION 03 · CHALLENGES

네 가지 함정 · 네 가지 해결

Wi-Fi 다중 호스트

DDS 멀티캐스트 패킷 유실

공유기 보안·QoS 정책으로 multicast 도달 실패 → 상태·로그 데이터 손실.

→ CycloneDDS unicast peers (cross-host-dds.md)

depth camera

스캔 거리에서 깊이 오차 ±20 mm

단일 중심점 depth 가 정반사·노이즈에 취약 → 잘못된 base_pose.

→ 2-phase grasp + ROI 중앙값 (grasp_node.py:880)

DSR action

장시간 grasp 콜백 단일 스레드 점유

VLM 5 초 + motion 10 초 동안 다른 콜백 starved → frame 갱신 멈춤.

→ MultiThreadedExecutor + Reentrant (grasp_node.py:406)

VLM latency

OpenAI API 가끔 30 초+ 지연

action_manager 동기 호출 시 BT tick 멈춤 + 사용자 응답 끊김.

→ call_async + 타임아웃 폴링 (action_manager.py:124)

각 함정은 발표 시 디버깅 로그 1줄 인용. "이 한 줄이 실마리였다" 식 스토리텔링.

SECTION 03 · LESSONS LEARNED

2주 프로젝트가 남긴 다섯 가지

01
책임 분리는 통신 단순화로 보답한다

14 노드 → 7 노드 통합 후 토픽 수가 ⅓ 로 줄고 디버깅 시간이 절반으로.

02
안전은 코드의 첫째 칸에 있어야 한다

음성 ESTOP·자동 홈 복귀를 후순위로 미루지 않고 1차 구현에 포함시켰기에 데모 사고 0.

03
실측 데이터가 곧 모델 성능이다

200+ 장 실측 추가만으로 YOLO fitness 0.65 → 0.93. 전문 모델 대신 데이터에 시간 투자.

04
오버 엔지니어링보다 단순 패턴이 강하다

service_is_ready() per call · autocommit=False · dedupe 5 초 — 모두 5줄 미만 패턴.

05
외부 API 는 항상 타임아웃

OpenAI 30 초 지연이 운영 중 한 번이라도 나면 시스템 전체가 죽는다. 동기 호출 금지.

회고는 추상적 표현 대신 사례 + 수치로 마무리. 마지막 슬라이드 Q&A 로 자연 전이.
